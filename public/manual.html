คู่มือการใช้งาน NN-LRMS

ระบบติดตามการคลอดแบบรวมศูนย์ จังหวัดน่าน (Nan Labor Room Monitoring System) — สำหรับเจ้าหน้าที่ห้องคลอด/หอผู้ป่วย สูติแพทย์และพยาบาลระดับจังหวัด และฝ่าย IT

ภาพรวม Flow การทำงาน เริ่มต้นใช้งาน เจ้าหน้าที่ห้องคลอด สูติแพทย์ / ระดับจังหวัด สิ่งที่ IT ต้องดูแล ปัญหาที่พบบ่อย

1. ภาพรวมระบบ

NN-LRMS รวบรวมข้อมูลหญิงตั้งครรภ์และผู้คลอดจาก HOSxP ของทุกโรงพยาบาลในจังหวัดน่านมาแสดงที่เดียว เพื่อให้ห้องคลอดของแต่ละโรงพยาบาลและโรงพยาบาลแม่ข่าย (รพ.น่าน) เห็นความเสี่ยงและตัดสินใจส่งต่อได้ทันเวลา

ข้อควรจำ ระบบเป็นเครื่องมือช่วยติดตามและสนับสนุนการตัดสินใจ ไม่ใช่เครื่องมือวินิจฉัย ไม่สั่งการรักษาหรือส่งต่อเอง และไม่แทนแนวทางเวชปฏิบัติหรือดุลยพินิจของแพทย์/พยาบาล

ข้อมูลมาจากไหน

ข้อมูลทั้งหมดบันทึกใน HOSxP เหมือนเดิม NN-LRMS ดึงไปแสดงเอง ไม่ต้องพิมพ์ซ้ำ ช่องทางหลักคือเปิด NN-LRMS จากเมนูใน HOSxP แล้วหน้าจอจะซิงค์ข้อมูลของโรงพยาบาลให้ทุก 60 วินาที โรงพยาบาลที่ไม่ใช้ HOSxP ส่งข้อมูลผ่าน Webhook API

ใครใช้ทำอะไร

  • ห้องคลอดดูบอร์ดเตียง บันทึก partograph/สัญญาณชีพ ย้ายเตียง ส่งต่อ จำหน่าย
  • จังหวัดสูติแพทย์/พยาบาลแม่ข่ายเฝ้าดูผู้คลอดทั้งจังหวัด ติดตามการส่งต่อ
  • ITดูแลการเชื่อมต่อ HOSxP เซิร์ฟเวอร์ สิทธิ์ และการซิงค์

2. Flow การทำงาน ตั้งแต่เริ่มจนสิ้นสุด

เส้นทางของหญิงตั้งครรภ์หนึ่งรายในระบบ ตั้งแต่ฝากครรภ์จนจำหน่ายและสรุปผลลัพธ์ทารก แต่ละขั้นระบุว่าใครทำและทำที่ไหน

HOSxPบันทึกในโปรแกรม HOSxP NN-LRMSระบบทำให้อัตโนมัติ ห้องคลอดเจ้าหน้าที่ รพ.ชุมชน จังหวัดสูติแพทย์/พยาบาลแม่ข่าย
ระยะที่ 1 · ฝากครรภ์

  1. HOSxPลงทะเบียนฝากครรภ์และบันทึกการตรวจ ANC

    เจ้าหน้าที่ ANC บันทึกใน HOSxP ตามปกติ (ประวัติครรภ์ ผลตรวจ การคัดกรองความเสี่ยง นัดครั้งถัดไป)

  2. NN-LRMSซิงค์ข้อมูลและสร้าง "เส้นทางการตั้งครรภ์"

    เมื่อมีหน้าจอ NN-LRMS ของโรงพยาบาลเปิดอยู่ ระบบดึงข้อมูลจาก HOSxP ทุก 60 วินาที จับคู่การตั้งครรภ์ข้ามโรงพยาบาลด้วยเลขบัตรประชาชนที่เข้ารหัสแล้ว และจัดระดับความเสี่ยง LOW / HR1 / HR2 / HR3

  3. จังหวัดห้องคลอดติดตามในเมนู "ฝากครรภ์"

    • กรองหา HR3, ใกล้ครบกำหนด, เลยกำหนด, ขาดนัด, ANC น้อยกว่าเกณฑ์
    • ระบบแจ้งเตือนตามที่ตั้งไว้ในโปรไฟล์ เช่น "ครรภ์เสี่ยงสูง (ANC HR3)", "ANC ขาดนัด", "ใกล้ครบกำหนดคลอด"
    • ติดตามผู้ที่ขาดนัดผ่านช่องทางปกติของโรงพยาบาล (โทรศัพท์ อสม. ฯลฯ)
ระยะที่ 2 · เข้าห้องคลอด

  1. HOSxPรับเข้าห้องคลอด (Admit) และจัดเตียง

    รับผู้คลอดเป็นผู้ป่วยในของวอร์ดห้องคลอดใน HOSxP พร้อมระบุห้อง/เตียง (roomno / bedno)

  2. NN-LRMSผู้คลอดขึ้นบนบอร์ดเตียงและแดชบอร์ดจังหวัด

    บอร์ด "ห้องคลอด" อ่านเตียงจาก HOSxP โดยตรงและรีเฟรชทุก 20 วินาที ระบบคำนวณคะแนน CPD และแสดงผู้คลอดบนแดชบอร์ดจังหวัดตามระดับความเสี่ยง

ระยะที่ 3 · เฝ้าระวังระหว่างรอคลอด

  1. ห้องคลอดบันทึก partograph และสัญญาณชีพตามรอบ

    บันทึกการเปิดของปากมดลูก การหดรัดตัว เสียงหัวใจทารก ความดัน ชีพจร อุณหภูมิ ฯลฯ ผ่านแท็บ "พาร์โทกราฟ" / "สัญญาณชีพ" ในหน้าผู้ป่วย หรือใน HOSxP ก็ได้ ข้อมูลเข้าที่เดียวกัน

  2. NN-LRMSประเมินและแจ้งเตือนอัตโนมัติ

    • กราฟ partograph พร้อมเส้น alert / action และกฎเตือน (CDSS) ด้านมารดา ทารก การหดรัดตัว และความก้าวหน้าการคลอด
    • เกิดการแจ้งเตือน เช่น "คะแนน CPD เสี่ยงสูง", "Partograph วิกฤต", "ภาวะฉุกเฉินในห้องคลอด" ไปยังผู้ที่ติดตามโรงพยาบาลนั้น และกลุ่ม LINE (MOPH) ของศูนย์กลางจังหวัดตามที่ผู้ดูแลตั้งไว้

  3. จังหวัดสูติแพทย์แม่ข่ายเฝ้าดูและให้คำปรึกษา

    ดูผู้คลอดเสี่ยงสูงทั้งจังหวัดบนแดชบอร์ด เปิดดูรายละเอียดผู้คลอด/partograph และใช้วิดีโอคอลปรึกษากับห้องคลอดต้นทางได้ทันที

ระยะที่ 4 · ตัดสินใจ

  1. ห้องคลอดจังหวัดคลอดที่โรงพยาบาลเดิม หรือส่งต่อ

    ก. คลอดที่โรงพยาบาลเดิมเฝ้าระวังต่อจนคลอด แล้วไปขั้นที่ 10
    ข. ส่งต่อในแท็บ "จำหน่าย" ของหน้าผู้ป่วย เลือกประเภท "ส่งต่อโรงพยาบาล" แล้วกรอกข้อมูลส่งต่อ (Refer Out) หรือออกใบส่งตัวใน HOSxP จากนั้นติดตามสถานะในเมนู "ส่งต่อ":
    INITIATED→ACCEPTED→IN_TRANSIT→ARRIVED
    หรือ REJECTED — ใบที่ค้างเกินเวลาจะขึ้นเตือน "ใบส่งต่อค้างเกินเวลา" เมื่อผู้ป่วยมาถึงปลายทาง ระบบยืนยันจากการรับตัวใน HOSxP ของโรงพยาบาลปลายทาง
ระยะที่ 5 · คลอดและสิ้นสุด

  1. ห้องคลอดHOSxPบันทึกการคลอดและข้อมูลทารก

    บันทึกระยะคลอด ยา ภาวะแทรกซ้อน และข้อมูลทารก (น้ำหนัก Apgar การกู้ชีพ) ในแท็บ "ระยะคลอด" / "ภาวะแทรกซ้อน" / "ทารก" หรือใน HOSxP

  2. ห้องคลอดจำหน่ายผู้ป่วย

    จำหน่ายในแท็บ "จำหน่าย" หรือใน HOSxP เตียงจะว่างบนบอร์ด และผู้คลอดออกจากรายการที่กำลังรอคลอด

  3. NN-LRMSจังหวัดสรุปผลลัพธ์

    ข้อมูลไปรวมในเมนู "ผลลัพธ์ทารก" (จำนวนคลอด น้ำหนักแรกเกิดต่ำ Apgar 5 นาที การกู้ชีพ ครรภ์แฝด) ใช้ทบทวนคุณภาพระดับจังหวัด เส้นทางการตั้งครรภ์ของรายนี้ถือว่าสิ้นสุด

เส้นทางของข้อมูล (ฝั่งเทคนิค)

สำคัญมาก: ระบบไม่ดึง HOSxP เองจากฝั่งเซิร์ฟเวอร์ ถ้าไม่มีหน้าจอ NN-LRMS ของโรงพยาบาลนั้นเปิดอยู่ (และไม่มี Webhook) ข้อมูลของโรงพยาบาลจะหยุดอัปเดต แดชบอร์ดจังหวัดจะขึ้นสถานะ "ล่าช้า" หลัง 60 นาที และ "วิกฤต" หลัง 24 ชั่วโมง

3. เริ่มต้นใช้งาน และการเข้าสู่ระบบ

ช่องทางเข้าสู่ระบบ

ช่องทางวิธีเข้าสิทธิ์
เปิดจากเมนูใน HOSxP (แนะนำ)เลือกเมนู NN-LRMS ใน HOSxP ระบบกรอก BMS Session ID และเข้าสู่ระบบให้อัตโนมัติอ่านและแก้ไขได้ ซิงค์ข้อมูลโรงพยาบาลได้

บทบาทผู้ใช้

  • พยาบาล และ สูติแพทย์ — ใช้งานทั่วไปตามโรงพยาบาลที่สังกัด
  • ผู้ดูแลระบบ — เจ้าหน้าที่ สสจ.น่าน (รหัสหน่วยบริการ 00042) เห็นเมนู "ตั้งค่า" เพิ่มเติม ต้องเข้าด้วย BMS และเลขบัตรต้องอยู่ในรายชื่อผู้ดูแลที่ IT ตั้งไว้ เจ้าหน้าที่ สสจ. ที่ไม่อยู่ในรายชื่อยังเข้าดูข้อมูลทั้งจังหวัดได้ แต่ไม่เห็นเมนูตั้งค่า

เมนูหลัก

เมนูใช้ทำอะไร
แดชบอร์ดภาพรวมจังหวัด: ผู้คลอดที่กำลังรอคลอด ความเสี่ยง การแจ้งเตือน แผนที่และสถานะโรงพยาบาล โหมดจอภาพ (Kiosk)
ฝากครรภ์ทะเบียนการตั้งครรภ์ข้ามโรงพยาบาล กรองตามระดับความเสี่ยง ใกล้/เลยกำหนด ขาดนัด
โรงพยาบาลรายชื่อโรงพยาบาลบนแผนที่ ภาระงาน ความสดของข้อมูล คุณภาพการบันทึก partograph
ส่งต่อติดตามใบส่งต่อทุกสถานะ ระยะเวลาค้าง เส้นทางการส่งต่อ
ผลลัพธ์ทารกสถิติการคลอดและทารกแรกเกิด แยกรายโรงพยาบาล
ห้องคลอดบอร์ดเตียงของโรงพยาบาลตัวเอง (อ่านจาก HOSxP โดยตรง)
โปรไฟล์ตั้งค่าการแจ้งเตือนที่ต้องการรับ (เข้าได้จากเมนู "การตั้งค่าการแจ้งเตือน" ที่มุมบนด้วย)
ตั้งค่าเฉพาะผู้ดูแลระบบ (ดูหัวข้อ สิ่งที่ IT ต้องดูแล)
คู่มือการใช้งานหน้านี้ — เปิดได้แม้ยังไม่เข้าสู่ระบบ

4. เจ้าหน้าที่ห้องคลอด / หอผู้ป่วย ต้องทำอะไรบ้าง

หลักการ: บันทึกงานใน HOSxP หรือในหน้าผู้ป่วยของ NN-LRMS ตามปกติ และ เปิด NN-LRMS ทิ้งไว้ บนเครื่องห้องคลอดตลอดเวร เพื่อให้ข้อมูลโรงพยาบาลส่งเข้าจังหวัดต่อเนื่อง

เริ่มเวร

  • เปิด HOSxP แล้วเข้า NN-LRMS จากเมนูใน HOSxP บนเครื่องห้องคลอด
  • เปิดเมนู "ห้องคลอด" ตรวจว่าผู้คลอดและเตียงตรงกับความจริง
  • ดูเวลาอัปเดตที่ป้ายสถานะ HOSxP มุมบน ต้องเป็นเวลาล่าสุด
  • ไล่ดูผู้คลอดที่มีคะแนน CPD สูง หรือมีป้ายเตือน

ระหว่างเวร

  • บันทึก partograph และสัญญาณชีพตามรอบเวลาที่กำหนด
  • ตอบสนองการแจ้งเตือน/คำปรึกษาจากแม่ข่าย
  • ย้ายเตียงในระบบเมื่อย้ายผู้ป่วยจริง (ต้องระบุเหตุผล)
  • บันทึกการคลอด ทารก และจำหน่ายให้ครบเมื่อจบเคส

ส่งเวร

  • ตรวจว่าไม่มีผู้ที่คลอด/จำหน่ายแล้วแต่ยังค้างบนบอร์ด
  • ตรวจใบส่งต่อที่ค้างสถานะ
  • อย่าปิดหน้าจอ NN-LRMS ให้เวรถัดไปใช้ต่อ

บอร์ดเตียง (เมนู "ห้องคลอด")

  • แต่ละช่องคือหนึ่งเตียง แสดงผู้คลอด ข้อมูลสำคัญ และสถานะ เตียงว่าง/ปิดใช้แสดงแบบย่อ
  • ด้านบนมีแผง "ความจุเตียง" และแผง "ต้องประเมินด่วน" ช่วยจัดลำดับว่าควรดูใครก่อน
  • ข้อมูลรีเฟรชเองทุก 20 วินาที กดปุ่มรีเฟรชเพื่ออัปเดตทันทีได้
  • ถ้ามีหลายวอร์ด เลือกวอร์ดได้ที่ส่วนหัว
  • ผู้ป่วยที่ยังไม่ได้จัดเตียง หรืออยู่เตียงเดียวกันหลายคน ยังแสดงให้เห็นทุกคน ควรแก้เตียงใน HOSxP ให้ถูกต้อง

ทารกข้อมูลทารกแรกเกิด
เตียงย้ายเตียง (หรือลากผู้ป่วยไปเตียงใหม่บนบอร์ด) ต้องระบุเหตุผล
จำหน่ายจำหน่ายผู้ป่วยออกจากห้องคลอด รวมถึงการส่งต่อ (เลือกประเภท "ส่งต่อโรงพยาบาล" แล้วกรอกข้อมูล Refer Out)

การส่งต่อทำในแท็บ จำหน่าย — ถ้าเลือกประเภทส่งต่อแต่ยังไม่กรอกข้อมูล Refer Out ระบบจะเตือน "ยังไม่มีข้อมูลส่งต่อ" หลังส่งแล้วติดตามได้ในเมนู "ส่งต่อ"

หลังย้ายเตียงหรือจำหน่าย ให้ตรวจผลทุกครั้ง การย้ายเตียงและจำหน่ายเขียนลง HOSxP หลายขั้นตอน ถ้าเครือข่ายสะดุดกลางทาง อาจสำเร็จเพียงบางส่วน ให้ตรวจบนบอร์ดและใน HOSxP ว่าตรงกัน หากไม่ตรงให้แก้ใน HOSxP แล้วกดรีเฟรช

ข้อควรปฏิบัติ

ควรทำ

  • บันทึกส่วนสูง น้ำหนัก ยอดมดลูก Hct ให้ครบ คะแนน CPD จะได้ไม่ต่ำกว่าความจริง
  • ระบุห้อง/เตียงใน HOSxP ให้ถูกต้องทุกครั้งที่รับเข้า
  • ออกจากระบบเมื่อใช้เครื่องร่วมกับผู้อื่นนอกห้องคลอด

ไม่ควรทำ

  • ถ่ายภาพหน้าจอข้อมูลผู้ป่วยส่งต่อในช่องทางที่ไม่ได้รับอนุญาต (PDPA)
  • ปิดหน้าจอ NN-LRMS บนเครื่องห้องคลอดระหว่างเวร
  • ใช้คะแนน CPD แทนการประเมินทางคลินิก

5. สูติแพทย์ / พยาบาลระดับจังหวัด (แม่ข่าย)

งานประจำวัน

  • เปิด "แดชบอร์ด" ดูผู้คลอดเสี่ยงสูงและการแจ้งเตือนล่าสุด
  • ตรวจแผงสถานะโรงพยาบาลว่าโรงพยาบาลใดข้อมูล "ล่าช้า" หรือ "ยังไม่ซิงค์" แจ้งโรงพยาบาลนั้นให้เปิด NN-LRMS จาก HOSxP
  • เปิดเมนู "ส่งต่อ" ดูใบส่งต่อที่รอตอบรับหรือค้างนาน
  • เปิดเมนู "ฝากครรภ์" ติดตามกลุ่ม HR3 ที่ใกล้ครบกำหนดหรือขาดนัด

เครื่องมือที่ใช้บ่อย

เครื่องมือวิธีใช้
ดึงข้อมูลทันทีปุ่มบนแดชบอร์ด ส่งข้อมูลของโรงพยาบาลตัวเองเข้าระบบทันที ไม่ต้องรอรอบ 60 วินาที
โหมดจอภาพ (Kiosk)ปุ่มบนแดชบอร์ด แสดงเต็มจอ ตัวอักษรใหญ่ สำหรับจอติดผนังในห้องคลอด/ห้องบัญชาการ กด Esc เพื่อออก
รายละเอียดโรงพยาบาลคลิกโรงพยาบาลบนแผนที่หรือรายชื่อ ดูผู้คลอด หญิงตั้งครรภ์ใกล้คลอด และสถานะการเชื่อมต่อ
รายละเอียดผู้คลอดคลิกชื่อผู้คลอด ดูสัญญาณชีพ การหดรัดตัว CPD partograph และประวัติการส่งต่อ
วิดีโอคอลเรียกผู้ใช้ที่ออนไลน์หรือทั้งโรงพยาบาลเข้าห้องปรึกษา (สูงสุด 8 คน) จากปุ่มที่ส่วนหัว

ตั้งค่าการแจ้งเตือน (เมนู "โปรไฟล์")

เลือกได้ทีละโรงพยาบาล ทีละเหตุการณ์ โรงพยาบาลของตัวเองได้รับรายละเอียดผู้ป่วย โรงพยาบาลอื่นที่เพิ่มเข้ามาติดตามจะได้รับเฉพาะยอดรวม ไม่ระบุตัวผู้ป่วย

เหตุการณ์ที่เลือกได้: ครรภ์เสี่ยงสูง (ANC HR3) · ภาวะฉุกเฉินในห้องคลอด · Partograph วิกฤต · คะแนน CPD เสี่ยงสูง · มีเคสส่งต่อเข้ามา · ใบส่งต่อค้างเกินเวลา · ANC ขาดนัด · ใกล้ครบกำหนดคลอด · ผลลัพธ์การคลอดผิดปกติ · การเชื่อมต่อข้อมูลขัดข้อง (บางรายการอาจยังไม่เปิดใช้ ระบบจะระบุไว้)

การอ่านตัวเลขบนแดชบอร์ด ตัวเลข ANC และผลลัพธ์นับจากข้อมูลที่ซิงค์เข้าระบบแล้วเท่านั้น ไม่ใช่จำนวนประชากรหญิงตั้งครรภ์ทั้งจังหวัด ถ้าโรงพยาบาลใดไม่ได้ซิงค์ ตัวเลขของโรงพยาบาลนั้นจะต่ำกว่าความจริง

6. สิ่งที่ IT ต้องดูแล

แบ่งเป็น 2 ระดับ: IT ของโรงพยาบาลชุมชน (ฝั่ง HOSxP และเครื่องห้องคลอด) และ IT / ผู้ดูแลระบบส่วนกลางที่ สสจ.น่าน (เซิร์ฟเวอร์และการตั้งค่าระบบ)

IT รพ.ชุมชนฝั่ง HOSxP และเครื่องห้องคลอด

งานรายละเอียด
เมนู NN-LRMS ใน HOSxPให้ผู้ใช้เปิด NN-LRMS จาก HOSxP ได้ (ส่ง BMS Session และ marketplace token มาให้) — ถ้าเปิดโดยไม่มี marketplace token ระบบจะดูได้แต่ไม่ส่งข้อมูลเข้าจังหวัด
เวอร์ชัน HOSxPต้องไม่ต่ำกว่าที่ระบบรองรับ ถ้าเก่าเกินจะขึ้นหน้าต่าง "ต้องอัปเดต HOSxP ก่อนใช้งาน" พร้อมเวอร์ชันขั้นต่ำ
BMS Session / local gatewayเครื่องห้องคลอดต้องเข้าถึง BMS gateway (เครื่องเดียวกัน 127.0.0.1:45011 หรือผ่าน BMS tunnel) และออกอินเทอร์เน็ตไปยังเซิร์ฟเวอร์ NN-LRMS ได้
webhook_setting ใน HOSxPครั้งแรกที่เปิดแดชบอร์ดด้วย session ที่ถูกต้อง ระบบสร้างแถว webhook_setting (module 3, code NN-LRMS) ให้อัตโนมัติ อย่าลบหรือแก้แถวนี้
ห้องและเตียงตั้งค่าห้อง/เตียง (roomno / bedno) ของวอร์ดห้องคลอดใน HOSxP ให้ครบ ถ้าไม่มี บอร์ดจะขึ้น "วอร์ดนี้ยังไม่มีเตียงใน HOSxP"
เครื่องห้องคลอดตั้งไม่ให้เครื่องเข้าโหมดพัก/ปิดเบราว์เซอร์เองระหว่างเวร เพราะการซิงค์ทำงานเฉพาะตอนหน้าจอเปิดอยู่ แนะนำ Chrome หรือ Edge รุ่นปัจจุบัน
โรงพยาบาลที่ไม่ใช้ HOSxPขอ Webhook API key จากผู้ดูแลส่วนกลาง แล้วให้ระบบของโรงพยาบาลส่งข้อมูลไปที่ POST /api/webhooks/patient-data (ดูรายละเอียดในหน้า เกี่ยวกับระบบ)

IT ส่วนกลางเซิร์ฟเวอร์และการตั้งค่าระบบ

การติดตั้งและค่าที่ต้องตั้ง

  • ติดตั้งด้วย Docker Compose (service app, postgres, redis) แล้ว deploy ด้วย npm run deploy ระบบสร้างตารางและข้อมูลโรงพยาบาลเริ่มต้นให้เองเมื่อเริ่มครั้งแรก
  • ค่าใน .env ที่ต้องตั้ง: POSTGRES_PASSWORD, NEXTAUTH_SECRET, ENCRYPTION_KEY (hex 64 ตัว), NEXTAUTH_URL (URL จริงของระบบ), ADMIN_ALLOWED_CIDS (เลขบัตรผู้ดูแล คั่นด้วยจุลภาค), ค่า BMS/ProviderID
  • ห้ามทำ ENCRYPTION_KEY หาย — ข้อมูลชื่อ/เลขบัตรที่เข้ารหัสไว้จะถอดไม่ได้อีก ต้องเก็บสำรองไว้ในที่ปลอดภัยแยกจากเซิร์ฟเวอร์
  • ADMIN_ALLOWED_CIDS ว่าง = ไม่มีใครเข้าเมนู "ตั้งค่า" ได้ ผู้ที่อยู่ในรายชื่อและเข้าด้วย BMS จะได้สิทธิ์ผู้ดูแลอัตโนมัติ
  • สสจ.น่าน (00042) เป็นหน่วยงานที่เข้าระบบได้โดยไม่ต้องลงทะเบียนเป็นโรงพยาบาล และไม่ถูกนับเป็นโรงพยาบาลที่ต้องซิงค์บนแดชบอร์ด ครั้งแรกที่เปิดจาก HOSxP ระบบสร้างรายการ "สำนักงานสาธารณสุขจังหวัดน่าน" ให้เอง เจ้าหน้าที่ สสจ. ทุกคนที่มี BMS session เข้าดูข้อมูลทั้งจังหวัดได้ จึงต้องคุมรายชื่อผู้ดูแลผ่าน ADMIN_ALLOWED_CIDS ให้รัดกุม
  • ใน production ต้องปิด DEV_AUTH_BYPASS และ DEV_SIMULATION_ENABLED (ระบบบล็อกให้เองอยู่แล้ว แต่ไม่ควรตั้งค่าไว้)
  • วาง reverse proxy / TLS (HTTPS) หน้าระบบ และให้ NEXTAUTH_URL ตรงกับ URL สาธารณะ

เมนู "ตั้งค่า" (เฉพาะผู้ดูแลระบบ)

แท็บใช้ทำอะไร
จังหวัดหลักกำหนดจังหวัดของระบบ (น่าน) — มีผลกับแผนที่และรายชื่อโรงพยาบาล
โรงพยาบาลเพิ่มจากทะเบียนสถานพยาบาล แก้ไข เปิด/ปิดใช้งาน กำหนดประเภทบริการ ล้างสถานะ "ระงับการซิงค์" เมื่อแก้ปัญหาแล้ว ดูจำนวนข้อมูลของแต่ละโรงพยาบาล
การเชื่อมต่อ BMSตั้งค่าการเชื่อมต่อ BMS ของแต่ละโรงพยาบาล
คีย์ Webhookออก/ยกเลิก API key สำหรับโรงพยาบาลที่ส่งผ่าน Webhook (คีย์แสดงครั้งเดียวตอนสร้าง)
สถานะการซิงค์ดูรอบการซิงค์ของทุกโรงพยาบาลย้อนหลัง 24 ชั่วโมง และเจาะดูรายละเอียดเมื่อมีปัญหา
ผู้ใช้ออนไลน์ดูว่าใครกำลังใช้งานอยู่ จากโรงพยาบาลใด
แจ้งเตือน MOPH (LINE)จัดการผู้รับการแจ้งเตือนผ่าน LINE ของศูนย์กลางจังหวัด
จำลองข้อมูลสำหรับเครื่องทดสอบเท่านั้น ห้ามใช้กับเซิร์ฟเวอร์จริง

ตารางงานดูแลระบบ

ทุกวัน

  • ตรวจ /api/health/ready ตอบ 200 และ /api/health ไม่อยู่ในสถานะ degraded
  • เปิด "ตั้งค่า → สถานะการซิงค์" หาโรงพยาบาลที่ล่าช้าเกิน 60 นาที ถูกระงับ หรือไม่เคยซิงค์ แล้วประสาน IT โรงพยาบาลนั้น
  • ตรวจว่าการสำรองฐานข้อมูลเมื่อคืนสำเร็จ

ทุกสัปดาห์

  • สคริปต์ล้างใบส่งต่อค้าง scripts/referral-cleanup-cron.sh รันตาม cron (แนะนำวันอาทิตย์ 03:30) ตรวจ log ว่าสำเร็จ
  • ตรวจพื้นที่ดิสก์ของ postgres-data/ และ redis-data/
  • ทบทวน log ของ app: docker compose logs app --since 24h

ทุกเดือน / เมื่อมีการเปลี่ยนแปลง

  • ทดสอบกู้คืนข้อมูลจาก backup (restore drill)
  • ทบทวนรายชื่อ ADMIN_ALLOWED_CIDS และคีย์ Webhook ที่ไม่ใช้แล้ว
  • อัปเดตระบบตามเวอร์ชันใหม่ ทดสอบก่อนขึ้นเครื่องจริง
  • บันทึกการเข้าถึง (audit log) เก็บ 30 วันแล้วลบเองอัตโนมัติ — หากนโยบายต้องเก็บนานกว่านี้ให้สำรองออกก่อน
ความปลอดภัยข้อมูล (PDPA) ชื่อและเลขบัตรประชาชนเข้ารหัสในฐานข้อมูล แต่ cache ใน Redis, ไฟล์ backup และ log อาจมีข้อมูลที่อ่านได้ ต้องจำกัดสิทธิ์เข้าถึงเซิร์ฟเวอร์ เข้ารหัส backup และกำหนดระยะเวลาเก็บตามนโยบาย สสจ.น่าน ระบบนี้ยังไม่มีการสำรองข้อมูลอัตโนมัติ ผู้ดูแลต้องตั้งเอง

7. ปัญหาที่พบบ่อยและวิธีแก้

อาการสาเหตุที่เป็นไปได้วิธีแก้ใครทำ
แดชบอร์ดขึ้นว่าโรงพยาบาลข้อมูล "ล่าช้า" / "ยังไม่ซิงค์"ไม่มีหน้าจอ NN-LRMS ของโรงพยาบาลนั้นเปิดอยู่ หรือเปิดโดยไม่ผ่าน HOSxPเปิด NN-LRMS จากเมนูใน HOSxP บนเครื่องห้องคลอด แล้วกด "ดึงข้อมูลทันที"ห้องคลอด
หน้าต่าง "ต้องอัปเดต HOSxP ก่อนใช้งาน"HOSxP เวอร์ชันเก่ากว่าที่รองรับอัปเดต HOSxP เป็นเวอร์ชันที่หน้าต่างแจ้ง แล้วเปิดใหม่IT รพ.
"ไม่ได้รับสิทธิ์ใช้งานระบบ" / "โรงพยาบาลถูกปิดการใช้งาน"โรงพยาบาลยังไม่ลงทะเบียน หรือถูกปิดใช้งานในระบบติดต่อผู้ดูแลระบบ สสจ.น่าน ให้เพิ่ม/เปิดใช้งานในเมนู "ตั้งค่า → โรงพยาบาล"IT ส่วนกลาง
สถานะ "ระงับการซิงค์" / ข้อมูลไม่ผ่านตรวจสอบข้อมูลที่ส่งมาไม่ตรงกับโรงพยาบาลที่ลงทะเบียนตรวจสอบสาเหตุ แล้วกด "เปิดใช้งานการซิงค์อีกครั้ง" ในเมนู "ตั้งค่า → โรงพยาบาล" จากนั้นให้โรงพยาบาลเปิด NN-LRMS จาก HOSxP ใหม่IT ส่วนกลาง
บอร์ดเตียงขึ้น "วอร์ดนี้ยังไม่มีเตียงใน HOSxP"ยังไม่ได้ตั้งค่าห้อง/เตียงของวอร์ดใน HOSxPเพิ่ม roomno / bedno ใน HOSxP หรือเลือกวอร์ดอื่นIT รพ.
ผู้ป่วยในบอร์ดไม่ตรงกับความจริงเตียงใน HOSxP ไม่ถูกต้อง หรือการย้าย/จำหน่ายสำเร็จบางส่วนแก้ใน HOSxP แล้วกดรีเฟรชบอร์ดห้องคลอด
เข้าด้วย ProviderID แล้วแก้ไขอะไรไม่ได้ProviderID เป็นสิทธิ์อ่านอย่างเดียวโดยตั้งใจเปิดจากเมนูใน HOSxP เพื่อใช้สิทธิ์บันทึกผู้ใช้
ไม่เห็นเมนู "ตั้งค่า"ไม่ใช่ผู้ดูแล หรือเข้าด้วย ProviderID หรือเลขบัตรไม่อยู่ใน ADMIN_ALLOWED_CIDSขอให้ IT ส่วนกลางเพิ่มเลขบัตร แล้วเข้าด้วย BMS ใหม่IT ส่วนกลาง
ไม่ได้รับการแจ้งเตือนยังไม่ได้เลือกเหตุการณ์/โรงพยาบาลในโปรไฟล์ตั้งค่าในเมนู "โปรไฟล์"ผู้ใช้
ทั้งระบบเข้าไม่ได้เซิร์ฟเวอร์หรือฐานข้อมูลล่มตรวจ docker compose ps, /api/health/ready และ log ของ appIT ส่วนกลาง
ข้อความแจ้งข้อผิดพลาดในระบบ ทุกข้อความบอกทั้งสิ่งที่ผิดพลาดและสิ่งที่ควรทำต่อ เมื่อต้องแจ้ง IT ให้ส่งข้อความนั้น พร้อมชื่อโรงพยาบาลและเวลาที่เกิดปัญหา
